# WWW 企业官网模板技能

WWW 用 CMS 栏目与文章组织品牌、服务、作品和新闻。首页的任务是让目标访客理解业务、看到足够的证据，并找到下一步入口。产品手册和 API 指南优先考虑文档模板。

## 每个 WWW 首页至少按这个顺序加载 5 个组件

无论客户资料是否足够，首页都展开至少这 5 个组件，顺序固定为 `hero4 → features3 → process1 → blogs2 → cta4`。缺图、缺购买链接、栏目还没有文章，都不能少装一段，也不能换成同族的其他变体。首屏写服务对象和能完成的任务，能力段列出用途，过程段解释合作方式，博客保留文章查询、循环、详情链接和空态，最后一段保留组件里的行动入口。可以在这 5 个之后再加其他区块。后续发布符合查询条件的文章后，同一首页会自动显示。

## 按访客任务选择区块

- 靠作品获得委托的平面设计工作室，把作品紧接在首屏之后。销售品牌策略的团队先用一段案例方法解释设计选择，再展示作品。两者都可能拥有同样的图片，阅读顺序取决于购买理由。
- 广告投放和社媒运营靠成果争取预算。有可披露的指标时，在服务或作品附近说明指标、周期与范围。只有服务材料时，展示交付流程与样例。
- SEO 和综合数字服务需要解释交付边界。服务分类之后可接常见问题、方法演示或关联项目。面向 App 用户时展示界面和下载入口；面向 App 开发采购方时展示步骤和项目交付。
- 内容营销和网站设计示例都用到了真实 CMS 查询。访客来查资料时保留搜索、最新与热门入口；访客来挑供应商时可将代表作品和项目咨询提前。RTL 模板中的预览画廊适合有多个可试用样例的产品。

每个首页的原始区块顺序、内容来源、适用条件和可替换组合见[11 个行业首页拆解](references/homepage-patterns.md)。查具体文件、交互依赖和资料要求见[85 个组件的选型目录](references/components.md)。

## 组装一个栏目暂时留空的首页

客户只提供产品定位、三项能力、工作步骤，或这些也还没写全时，首页仍然使用上一节的 5 个组件。此组合无需创建示例文章。若取得了公开作品，可以在这 5 个之后追加作品区块，不替换前面的固定顺序。博客在有新闻发布后按查询范围自动显示文章。

## 区块、布局和内容的来源

- `templates/index.sections.liquid` 是组件组装入口，源码里只有 hero7 默认启用，页面 Schema 为 `settings: []`。以 `{% render 'components/services3' %}` 为例，组件源码在 `snippets/components/_services3.liquid`。首页的 layout 已包含公共页头页脚。
- `templates/index.*.liquid` 是完整首页。其页面设置和内联代码随变体而异。历史展示页 `statics/index-branding.liquid` 和 `statics/snippets/hero.liquid` 可供查看构图，不要把展示页整页复制到本站首页。
- 五个 blogs 变体默认读全站符合条件的 page。需要新闻或案例专栏时绑定目标栏目；没有文章时检查整个区块的空态。服务卡、作品、标志与多数数字组件自带演示内容，要替换为客户资料。
- 栏目和文章使用当前版本 Schema 的父子关系。页头、页脚菜单使用已建页面的路径。详情、栏目、搜索等页面的版式另见[内页参考](references/interior-pages.md)。

## 事实边界与维护

演示价格、客户标志、评价、人物、统计数字需逐项核对来源和使用权。搜索行动区可复用模板的站内搜索；咨询与订阅组件需接入有效接口才可承诺收件。使用当前组织有权使用的媒体；检查标题可读、图片比例、目标链接和移动端交互。

首页经 AI 修改时，根据可见文案与组件来源定位本站实例，保留真实栏目查询、媒体和其他实例的修改。页面已有展开源码时直接编辑该区块。工作台候选、预览和采用约束见[工作台维护](references/workbench.md)。页面字段以 manifest 与该版本的 Schema 为准，标签通过授权选择器引用已有 IID。
