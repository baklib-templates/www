# WWW 工作台执行约束

## 局部选区与候选继承

选区是定位附件，不是可以直接粘进聊天或模板的源码。先根据当前预览版本、文件路径、section/snippet 引用定位真实源码；沿用上一份已验证候选作为基线，避免后一处修改覆盖前一处成果。大文件按区域及关联片段读取，不要求用户判断模板文件大小。

## 首页局部改写

从本站当前采用的 `templates/index.sections.liquid` 及其最新候选开始。核对页面是 render 引用还是已经展开了源码，再通过区块标识、组件来源和可见内容找到客户点名的实例。只改这一个实例中的文案、图片、按钮或布局，继续使用现有分组、动态栏目查询与实际页面路径。例如「把首屏按钮改成预约演示」只修改首屏按钮文案；客户同时指定新的目的地时再改链接。保存前比较其余区块与人工修改，采用后打开目标页面核对结果。

首页中已展开的实例属于本站。共享组件文件作为后续取样的源文件；更新模板库或另一个同类实例应另有明确需求。旧站仍按其固定版本支持的字段和编辑方式处理。

## 设计与开发交付

复用当前 layout、snippet、组件与样式，只修改需求涉及的区域。保留原有媒体引用、内容模型和表单接口；不以静态联系表单宣称已支持业务提交。按需运行 Liquid/Schema、CSS/JS构建、真实页面检查；布局变化检查桌面与手机。失败保留最近可用预览，不能把模型返回代码或候选 ready 当作已采用。

## 标签组与旧数据

页面字段保持 tags/tag_picker，标签值使用当前站点的 IID。组与父节点使用稳定 tag_group/tag_root 键，词表必须先存在；普通官网默认不固定组，保留旧未分组标签。按 group_key 分组、显示 group_name/ancestor_names，不能按同名标签推断组或父子关系。标签页默认精确匹配；包含下级必须显式选择。AI 内容写入器尚不支持通用 tag_picker 字段，不可臆造标签 ID 绕过选择器。

## 采用与权限

候选检查通过后由入口策略决定采用；新建站首轮授权不能套用到已有站点或共享模板分支。删除、覆盖人工内容、替换模板与共享影响须明确说明。恢复设计不回滚已确认正文和标签数据。

## 字段与媒体

公共设置使用当前版本 manifest 允许的字段和 Schema 类型。正文写入页面的 content，摘要写入 description；依赖全站配置的枚举须选已有选项。媒体从当前组织授权资源中取得，保留真实 DAM 引用。把外部文案放入 Liquid 源码时以文本处理，避免其中的模板标记被执行。

同一组件在本站出现多次时，保留可区分的实例标识和来源，更新该实例内关联的 DOM id、锚点和表单目标。用可见标题或按钮文字确认改动命中了运营人员点名的那一处。
